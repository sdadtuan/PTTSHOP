# P0-1 và P0-3 — sao lưu rồi triển khai `fix/remove-demo-credentials`

Commit sửa fetch/checkout chưa push. Lần triển khai sau chỉ chạy script trong repo, sau khi commit đó có trên `origin`. Không dùng bản chép `/root/pttshop-update.sh`. Triển khai chỉ chạy sau câu **OK deploy**.

Không chạy seed. Script không dùng `git reset --hard`, `git clean`, `migrate reset` hay `db push`.

## Trước khi triển khai

1. Anh duyệt `deploy/update.sh`.
2. Anh nói rõ được push. Lệnh push (chưa chạy):

```bash
git push -u origin fix/remove-demo-credentials
```

3. Trên VPS, xác nhận user dịch vụ:

```bash
systemctl show pttshop -p User
```

## P0-1 và triển khai mã

`deploy/update.sh` tự làm P0-1 rồi mới đổi mã:

- dừng nếu thiếu `DEPLOY_BRANCH`;
- dừng nếu `/var/www/pttshop` còn thay đổi chưa commit;
- sao lưu `/var/www/pttshop/data/prod.db` vào `/var/backups/pttshop/prod-<TS>.db` và chỉ tiếp tục khi `PRAGMA integrity_check` in `ok`;
- `git fetch` bằng refspec có đích, `git checkout -B` đúng commit remote, dừng nếu nhánh local lệch remote;
- `npm ci`, rồi dừng nếu `_prisma_migrations` chưa có `0_init`;
- khi đã baseline: `prisma migrate deploy`, `npm run build` bằng user của dịch vụ;
- `systemctl restart pttshop`;
- kiểm tra `http://127.0.0.1:3400/` và `/dang-nhap` đều trả 200.

Nếu một bước lỗi, script in hướng dẫn quay lui về commit trước và bản sao lưu vừa tạo. Script không tự quay lui.

## Baseline một lần

Schema của nhánh này trùng commit đang chạy trên production. `User.password` đã nullable. Production tạo bằng `db push`, chưa có `_prisma_migrations`. Baseline trong repo là `prisma/migrations/0_init` (provider sqlite trong `migration_lock.toml`).

Chạy script trước. Script sao lưu, checkout nhánh, rồi mở `prod.db` bằng `sqlite3 -readonly`. Nếu chưa có bảng `_prisma_migrations`, hoặc chưa có dòng `migration_name = '0_init'`, script dừng và in:

```text
Chưa baseline. Chạy một lần: cd /var/www/pttshop && sudo -u <user> npx prisma migrate resolve --applied 0_init, rồi chạy lại script.
```

`<user>` là user dịch vụ mà script đã đọc. Lệnh resolve chỉ ghi bảng `_prisma_migrations`, không đổi dữ liệu. `die` cũng in hướng dẫn quay lui. Với đúng thông báo này, không checkout commit cũ: mã đã là bản có `0_init`, database chưa bị migrate. Chạy lệnh resolve, rồi chạy lại script. Lần sau bước kiểm tra thấy `0_init` và script mới gọi `prisma migrate deploy`.

Chạy từ repo. Không dùng `/root/pttshop-update.sh`.

```bash
cd /var/www/pttshop
DEPLOY_BRANCH=fix/remove-demo-credentials ./deploy/update.sh
```

Sau đó mở trang chủ và `/dang-nhap`. Trang đăng nhập không còn gợi ý tài khoản. `/demo-v2` trả 404.

## P0-3 · Đổi admin và AUTH_SECRET

Anh tự chạy trên VPS, bằng root. Không dán mật khẩu hay `AUTH_SECRET` vào chat. `set +x` để shell không in giá trị. Mật khẩu cần ít nhất 12 ký tự, có chữ hoa, chữ thường và số.

`systemctl edit` ghi drop-in `Environment=AUTH_SECRET=...`. Unit đang có `EnvironmentFile=`, và systemd để file này ghi đè `Environment=`. Drop-in vì vậy cũng trỏ một file root đọc sau `.env`, cùng giá trị, để secret mới có hiệu lực. File đó không in ra màn hình.

```bash
set +x
umask 077
install -d -m 700 /var/backups/pttshop
ts=$(date +%Y%m%d-%H%M%S)
backup=/var/backups/pttshop/prod-$ts.db
sqlite3 /var/www/pttshop/data/prod.db ".backup '$backup'"
test "$(sqlite3 "$backup" 'PRAGMA integrity_check;')" = ok
echo "Đã sao lưu $backup"

cd /var/www/pttshop
service_user=$(systemctl show pttshop -p User --value)
read -r -s -p "ADMIN_EMAIL: " ADMIN_EMAIL; echo
read -r -s -p "ADMIN_PASSWORD: " ADMIN_PASSWORD; echo
export ADMIN_EMAIL ADMIN_PASSWORD
sudo --preserve-env=ADMIN_EMAIL,ADMIN_PASSWORD -u "$service_user" \
  bash -lc 'cd /var/www/pttshop && set +x && email=$ADMIN_EMAIL && pass=$ADMIN_PASSWORD && set -a && [ -f .env ] && . ./.env && set +a && export ADMIN_EMAIL=$email ADMIN_PASSWORD=$pass && unset email pass && npm run rotate-admin'
unset ADMIN_EMAIL ADMIN_PASSWORD

secret_file=$(mktemp)
editor=/root/pttshop-systemctl-edit
openssl rand -base64 32 | tr -d "\n" > "$secret_file"
cat > "$editor" << EOF
#!/bin/sh
set +x
secret=\$(cat ${secret_file})
install -d -m 755 /etc/pttshop
printf 'AUTH_SECRET=%s\n' "\$secret" > /etc/pttshop/auth-secret.env
chmod 600 /etc/pttshop/auth-secret.env
printf '%s\n' '[Service]' "Environment=AUTH_SECRET=\${secret}" 'EnvironmentFile=/etc/pttshop/auth-secret.env' > "\$1"
EOF
chmod 700 "$editor"
sudo env SYSTEMD_EDITOR="$editor" systemctl edit pttshop --drop-in=auth-secret
rm -f "$secret_file" "$editor"
unset secret_file editor
chmod 600 /etc/systemd/system/pttshop.service.d/auth-secret.conf
systemctl daemon-reload
systemctl restart pttshop
```

Script rotate in `Đã cập nhật admin <email>; đã khoá N tài khoản demo.` Không in mật khẩu. Nếu `systemctl restart` lỗi, không checkout mã. Gỡ secret mới rồi bật lại dịch vụ bằng secret cũ:

```bash
systemctl stop pttshop
rm -f /etc/systemd/system/pttshop.service.d/auth-secret.conf /etc/pttshop/auth-secret.env
systemctl daemon-reload
systemctl start pttshop
systemctl is-active pttshop
```

Nếu cần trả lại cả mật khẩu admin, dùng đúng bản sao lưu vừa tạo:

```bash
systemctl stop pttshop
cp "$backup" /var/www/pttshop/data/prod.db
chown "$service_user:$service_user" /var/www/pttshop/data/prod.db
systemctl start pttshop
```

Kiểm tra chỉ đọc, không thử đăng nhập bằng tài khoản demo:

```bash
sudo -u "$(systemctl show pttshop -p User --value)" sqlite3 /var/www/pttshop/data/prod.db \
  "SELECT email, role, CASE WHEN password IS NULL THEN 'locked' ELSE 'has-password' END FROM User WHERE email IN ('admin@pttshop.vn','khach@pttshop.vn');"
```

Kỳ vọng: cả hai dòng `CUSTOMER` và `locked`.

Sau restart, trên máy chủ: `systemctl is-active pttshop` là `active`, `curl -sS -o /dev/null -w '%{http_code}' http://127.0.0.1:3400/dang-nhap` là `200`. Trên trình duyệt: mật khẩu admin cũ bị từ chối; mật khẩu mới vào được trang quản trị; tab đã đăng nhập từ trước bị đăng xuất. Không đặt mật khẩu vào lệnh curl.
